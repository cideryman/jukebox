# 주크박스 - 영구 로컬 저장(우선순위 1) 작업 결과 보고서

## 1. 독립적 검토 및 문제 해결 (Self-Audit & Fixes)

DESIGN.md의 요구사항과 사용자 경험(UX) 계약을 바탕으로 `antigravity/persistent-storage` 브랜치의 변경 사항을 심층 검토했으며, 발견된 문제를 모두 직접 수정했습니다.

### 🔴 주요 문제 및 해결 내용 (중요도순)

#### 1. 영구 저장 API 오류 시 앱 먹통 회귀 (UX 계약 위반)
- **문제점**: OPFS 접근 권한이 없거나 기기 용량이 부족하여 `storage.saveSlotFile`이 실패할 경우, 파일 등록 로직이 완전히 실패하며 앱이 먹통이 되는 회귀가 있었습니다. 이는 "영구 저장 API가 없어도 기본 화면과 터치 재생은 계속 동작해야 한다"는 DESIGN.md의 핵심 요구사항 위반입니다.
- **수정 내용**: `app.js`의 `registerFile` 및 `clearSlot`에 인메모리(in-memory) 폴백(Fallback) 로직을 추가했습니다. 영구 저장이 실패하면 오류 로그를 남긴 후, 해당 세션에 한해 기존처럼 RAM 메모리에 파일을 등록하도록 조치했습니다. 앱 재시작 시에는 초기화되지만, 당장 재생하는 데는 문제가 없도록 보장합니다.

#### 2. 빠른 연속 등록과 재생의 경쟁 상태 (Race Condition)
- **문제점**: 사용자가 파일을 선택하여 OPFS에 저장 중인 상태(비동기 I/O 진행 중)에서 보호자 설정을 닫고 해당 슬롯의 타일을 클릭하면, 이전 파일을 재생하려고 시도하다가 저장이 완료되는 순간 객체 URL이 강제 회수되며 오류가 발생할 수 있었습니다.
- **수정 내용**: `app.js`에 `savingSlots` (Set 자료구조)를 추가하여 슬롯 잠금(Lock) 메커니즘을 구현했습니다. 파일이 저장되거나 삭제되는 동안에는 해당 슬롯의 타일과 보호자 설정 내의 버튼들이 비활성화(`disabled`) 상태가 되며 로딩 UI가 표시됩니다.

#### 3. 객체 URL(Object URL) 메모리 누수
- **문제점**: (매우 드문 경우지만) `loadPersistedSlots`가 중복 호출될 경우, 기존에 할당된 `URL.createObjectURL`을 해제(`revokeObjectURL`)하지 않고 새 URL을 덮어씌워 메모리 누수가 발생할 수 있었습니다.
- **수정 내용**: `loadPersistedSlots` 함수 시작 부분에 `revokeAllObjectUrls()`를 호출하여 기존 메모리를 확실하게 해제하도록 수정했습니다.

#### 4. 안드로이드 크롬 PWA 백그라운드 재생 및 접근성 점검 (이상 없음)
- **점검 결과**: `navigator.mediaSession` 메타데이터 등록 시 OPFS에서 로드한 Blob의 타입(`file.type`)이 정상적으로 유지됨을 확인하여 백그라운드 재생(알림창 컨트롤 및 썸네일)에 문제가 없음을 검증했습니다. 기존의 접근성(ARIA 레이블) 코드도 모두 원형 그대로 보존되었습니다.

## 3. 남은 위험 (Risks & Limitations)

현재 구현으로 1순위 요구사항을 달성했으나, 다음과 같은 기술적 한계가 존재합니다.

1. **사파리(iOS) 지원 한계**: OPFS는 비교적 최신 기술이므로, 구형 iOS 기기에서는 동작하지 않을 수 있습니다. 이번 업데이트로 폴백(Fallback) 기능이 적용되어 구형 기기에서도 당장 앱이 고장 나지는 않지만, "영구 저장" 기능 자체는 최신 기기(iOS 15.2+)에서만 완벽히 동작합니다.
2. **서비스 워커 캐시 타이밍**: 캐시 우선(Cache-First) 전략 특성상, 사용자가 처음 앱을 켤 때는 이전 버전의 코드가 실행될 수 있습니다. 브라우저가 백그라운드에서 새 `sw.js`를 감지하고 강제 갱신(`skipWaiting`)하도록 조치했으나, 가장 확실한 적용을 위해서는 새로고침이 한 번 필요할 수 있습니다.
3. **OPFS 용량 상한**: 브라우저별로 OPFS에 할당하는 하드 디스크 용량 상한이 다릅니다. 고음질 파일을 무한정 저장할 경우 언젠가 제한에 도달할 수 있으며, 이 경우 UI에 표시된 저장 용량 게이지를 통해 보호자가 직접 관리해야 합니다.
