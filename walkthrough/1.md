## 3. 데이터 저장 구조

```
[브라우저 로컬 저장소]
│
├── IndexedDB (데이터베이스: "jukebox_db", 스토어: "slots", keyPath: "id")
│   └── 1~9번 슬롯 메타데이터
│       ├── id: 1 ~ 9
│       ├── audioFileName / audioMime / audioPath (OPFS 내부 파일명)
│       ├── imageFileName / imageMime / imagePath (OPFS 내부 파일명)
│       ├── label: "곡명 (보호자 화면 및 Media Session 전용)"
│       └── updatedAt: 타임스탬프
│
└── OPFS (Origin Private File System, 디렉터리: "media/")
    └── UUID 기반의 안전한 바이너리 파일
        ├── slot_1_audio_xxxxxxxx.mp3
        ├── slot_1_image_xxxxxxxx.jpg
        └── ...
```

### 안정성 보장 메커니즘
1. **원자적 저장 (Safe Write)**:
   - 새 파일을 OPFS에 기록 및 검증 -> IndexedDB 메타데이터 갱신 -> 성공 후 이전 OPFS 파일 삭제
   - 중간 실패 시 새로 작성된 임시 파일을 삭제(롤백)하고 기존 슬롯 데이터 보존
2. **슬롯 동시성 제어 (Mutex Queue)**:
   - 동일 슬롯에 빠른 연속 변경 요청 시 큐 직렬화를 통해 마지막 작업의 결과만 유효하게 반영
3. **고아 파일 정리 (Garbage Collection)**:
   - 앱 초기화 시 OPFS의 실제 파일 목록과 IndexedDB에 등록된 경로를 대조하여 미참조 파일 자동 삭제
4. **내결함성 (Fault Tolerance)**:
   - 특정 슬롯의 파일이 누락되거나 손상되어도 해당 슬롯만 오류 처리하고, 다른 8개 슬롯은 정상 로드 및 재생 가능

## 4. 검증 결과

### 1) 자동화 테스트 스위트 (`test.html`) — **10/10 PASS**
1. `storage.init()` 초기화 및 IDB/OPFS 연결 -> **PASS**
2. 슬롯 1 & 2 음원/사진 영구 저장 (`saveSlot`) -> **PASS**
3. `listSlots()` 호출 시 1~9번 슬롯 복원 및 File 객체 재구성 -> **PASS**
4. `storage.estimate()` 저장 공간 및 영구 저장 상태 반환 -> **PASS**
5. 슬롯 1 이미지 교체 시 이전 OPFS 파일 삭제 및 신규 파일 저장 -> **PASS**
6. 슬롯 2 삭제 (`removeSlot`) 시 메타데이터 및 모든 OPFS 파일 삭제 -> **PASS**
7. 슬롯 파일 손상 내결함성 (손상 슬롯만 에러 처리, 타 슬롯 정상 로드) -> **PASS**
8. 동일 슬롯 빠른 연속 변경 시 큐 직렬화로 최종 결과 정상 반영 -> **PASS**
9. `init()` 실행 시 참조되지 않는 고아 OPFS 파일 자동 정리 -> **PASS**

### 2) 브라우저 실환경 E2E 검증
* **새로고침 복원**: 새로고침 및 탭 재시작 후 1~9번 슬롯의 음원과 썸네일이 즉시 복원됨
* **재생 계약**: 복원된 카드 터치 시 즉시 재생, 동일 카드 재터치 시 정지 및 처음으로 되감기, 다른 카드 터치 시 이전 음악 정지 후 새 음악 단일 재생
* **설정 진입**: 톱니 짧은 터치 시 미진입(토스트 안내), 2초 길게 누르면 보호자 설정 오픈
