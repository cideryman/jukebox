# 데이터 안전 수정 및 병합 전 검증 결과

## 1. 수정한 문제

Codex 검토에서 확인한 다음 문제를 수정했다.

1. 테스트 저장소가 실제 앱의 슬롯 1~4를 덮어쓰고 삭제하던 문제
   - `JukeboxStorage`가 DB 이름과 OPFS 디렉터리 이름을 주입받도록 변경했다.
   - `test.html`은 `jukebox_test_db`와 `media-test/`만 사용하고 실행 시작 시 초기화한다.
2. IndexedDB 요청 성공을 트랜잭션 커밋 완료로 잘못 간주하던 문제
   - 쓰기와 삭제는 `transaction.oncomplete`에서만 성공 처리한다.
   - `error`와 `abort`는 모두 실패로 처리한다.
3. 영구 삭제 실패 후 화면만 비우고 성공으로 안내하던 문제
   - 삭제 실패 시 기존 슬롯 상태를 유지하고 보호자에게 재시도 오류를 표시한다.
   - 영구 데이터가 전혀 없는 인메모리 전용 슬롯은 저장 API 없이도 정상적으로 비울 수 있다.
4. 초기화 경쟁 상태
   - 모든 호출이 하나의 `initPromise`를 기다리도록 변경했다.
5. 음원 교체 후 이전 Media Session 곡명이 남던 문제
   - 새 음원 파일명으로 `label`을 갱신한다.
6. 슬롯 작업 큐가 완료 뒤 정리되지 않던 문제
   - 큐에 실제 저장한 Promise와 비교해 완료된 슬롯 항목을 제거한다.
7. 서비스 워커 검증의 거짓 양성
   - 활성 서비스 워커, 현재 캐시 버전, 필수 앱 셸 파일을 실제로 확인한다.
8. 테스트 페이지 방문이 오프라인 앱 셸을 오염시키던 문제
   - 루트 또는 `index.html` 응답만 오프라인 `index.html` 캐시를 갱신한다.
   - 캐시 버전을 `jukebox-shell-v4`로 올렸다.

## 2. 검증 결과

### 정적 검사

- `node --check app.js`: 통과
- `node --check storage.js`: 통과
- `node --check sw.js`: 통과
- `git diff --check`: 통과

### 브라우저 저장소 테스트

격리된 로컬 출처에서 다음 결과를 확인했다.

- 첫 실행: 10/10 통과
- 같은 탭에서 즉시 재실행: 10/10 통과
- 동시 `storage.init()` 호출: 통과
- 같은 슬롯에 빠른 연속 저장 후 마지막 파일·곡명 유지: 통과
- 완료된 슬롯 큐 정리: 통과
- 서비스 워커 활성화 및 `jukebox-shell-v4` 필수 파일 캐시: 통과

### 운영 데이터 격리

테스트 실행 직후 같은 출처에서 실제 앱을 열었을 때 사용자 카드가 생성되지 않았다. 테스트 데이터가 운영 `jukebox_db`와 OPFS `media/`에 기록되지 않음을 확인했다.

### 오프라인 앱 셸

1. 온라인에서 테스트 페이지와 실제 앱을 차례로 열었다.
2. 로컬 서버를 종료했다.
3. `/` 주소의 실제 앱을 새로고침했다.
4. 테스트 러너가 아니라 `나의 주크박스` 화면이 오프라인으로 정상 복원됐다.

## 3. 아직 구현하지 않은 후속 기능

다음 사용자 요청은 이번 안전 수정 범위에 포함하지 않았으며 `HANDOFF.md`에 구현 계약과 테스트 기준을 정리했다.

- MP3 내장 앨범아트를 기본 썸네일로 사용하는 기능
- 보호자가 직접 선택한 이미지로 앨범아트를 덮어쓰는 기능
- 보호자용 최대 음량 상한 설정
